冯越的方法论如下：
方法论
冯越的方法论可以概括为一句话：
不要从“我能改哪个模型、加哪个模块”出发，而要同时从“领域真正缺什么能力”和“哪些高层思想可以迁移过来”两端出发，用系统调研验证二者是否能够严密对接。
一、核心框架：两条路线并行
路线一：自下而上，吃透目标领域
先全面理解 Coding Agent，而不是先挑一篇 baseline 想三个改进点。
需要回答：
●领域目前有哪些核心任务、能力和问题？
●这些分类是否处于同一抽象层级？
●企业和大厂真正关心什么？
●哪些方向只是学术玩具，哪些具有实际价值？
●每个问题为什么过去做不好？
●现有方法解决到了什么程度，真正的瓶颈在哪里？
调研的产物不应只是“八类论文列表”，而应是一张能力—问题—方法地图：
缺什么能力 → 为什么缺 → 现有方法怎么做 → 方法局限在哪里 → 哪些环节决定成败。
路线二：自上而下，引入高层思想
另一条路线是积累能够跨领域迁移的“思想标签（tag）”，例如：
●信息论与熵
●主动感知、想象—验证
●程序性知识
●latent knowledge
●表征或能力对齐
●柏拉图表征假说一类的现象性假说
●多模型能力融合
●文档压缩、持续学习、测试时训练等成熟领域的方法论
重点不是机械套用某个技术，而是提炼其背后的哲学思想、现象或机制，再问：
这个思想在 Coding Agent 中是否存在对应问题？两个问题在本质上是否等价？
最终的创新来自两条路线交汇：
真实领域需求 × 高层思想迁移 × Coding 场景的本土化适配。

二、好选题必须同时具备“动机”和“tag”
冯越反复强调两个要素。
1. 动机：领域为什么真正需要它
动机不是“某篇 baseline 有三个缺点”，而是：
●Coding Agent 缺少什么核心能力？
●这个问题是否真实、重要且普遍？
●为什么已有方法无法解决？
●为什么现在值得解决？
●企业、强机构和主流研究是否认可这个需求？
2. Tag：用什么有辨识度的思想解决
Tag 是论文的思想标签，例如“从轨迹级监督变成步骤级监督”“基于内部熵判断推理可靠性”“对齐不同模型的能力空间”。
但 tag 有层次：
●低级：在某个 baseline 上贴一个新模块。
●中级：把其他领域已经成熟的方法迁移过来。
●高级：从某种假说、现象或理论出发，重新定义问题和解决范式。
同时要解释：
●为什么选这个 tag？
●为什么不是其他理论？
●该理论具体是哪一条公式、机制或可检验假设？
●它和目标问题的对应关系是什么？
“信息论”这种大词本身不构成方法，必须具体到熵、互信息、信息增益等可计算对象。

三、创新的主要来源：跨领域的信息差
冯越认为，不必完全依靠闭门原创。更高效的方式是：
1.把 Coding Agent 的问题抽象成一个更一般的问题。
2.找到已经高度发展的相邻领域。
3.比较两个领域的技术成熟度。
4.把成熟领域的思想迁移过来。
5.做必要且关键的领域适配。
例如：
●上下文记忆 ≈ 文档压缩、长文本总结、记忆更新；
●Coding Agent 的持续改进 ≈ 持续学习、测试时训练；
●轨迹奖励分配 ≈ 强化学习中的信用分配；
●多模型协作 ≈ 表征对齐、能力融合；
●工具调用与信息获取 ≈ 主动感知、信息增益决策。
如果通用领域已经发展到“10”，而 Coding Agent 里只发展到“5”，中间就是可以利用的信息差。
不过，迁移必须满足两个条件：
●两端问题在本质上确实对应；
●Coding 场景的适配是决定成败的，而不是换个数据集包装。

四、读论文：看思想，不只看作者声称的贡献
冯越主张把论文拆成几个层次来读：
1.它真正解决了什么问题？
2.核心变化发生在哪个抽象层级？
3.它的思想从哪里来？
4.是真正提出新范式，还是从其他领域迁移？
5.哪部分是普适思想，哪部分是场景包装？
6.这个思想还能迁移到哪些任务？
即使一篇论文的假说最终不成立，也仍然可以提供价值：
●暴露一种值得搜索的现象；
●提供一种新的观察尺度；
●引出一批类似假说；
●启发其他场景中的实验设计。
因此，论文阅读的目标不是简单积累“做法”，而是建立一个可复用的思想库。

五、对具体 idea 的检验标准
一个 idea 至少要经受以下检查：
●Baseline 是否真正讲清楚了？
●所谓缺点是否真实存在，而不是为了写论文人为制造？
●缺点属于通用算法，还是 Coding 特有问题？
●提出的方法是否真正解决了该缺点？
●理论、机制和公式是否明确？
●为什么这个理论适用于该环节？
●通用领域是否早已有人做过？
●Coding 领域是否真的没有做，或者只完成了一小部分？
●最强 baseline、基础模型和实验比较是否公平？
●论文声称的贡献与实验真正证明的内容是否一致？
他尤其反对两类 idea：
●只围绕单篇 baseline 做“一二三点修改”；
●使用“信息论、记忆、主动感知”等大词，却说不清具体机制。

六、如何使用 AI
冯越并不反对使用 AI，但强调人与 AI 的分工。
人的职责：
●提出第一批有深度的直觉和假设；
●判断两个问题是否本质等价；
●判断迁移是否真有必要；
●判断需求是否真实；
●决定哪个方案最有价值。
AI 的职责：
●广泛搜索相关论文和现象；
●验证是否撞车；
●检查相邻领域是否已有类似方法；
●把论文拆成不同技术模块；
●比较多个落地方案；
●帮助放大、调整和淘汰初始想法。
也就是：
人先形成方向性判断，AI负责扩展和验证，最后仍由人做科研判断。
不能把 AI 生成的“缺点—方法—贡献”直接当作自己的思考。

七、审稿与做研究使用同一套判断体系
冯越把审稿视为训练科研判断力的手段。审稿时应判断：
●是增量式创新，还是范式升级？
●原方法是否真有作者声称的缺点？
●改进是否真正解决问题？
●所谓新范式是不是从别的领域搬来的？
●领域适配是否充分？
●对比是否公平？
●baseline 是否足够强？
●作者声称的东西是否被实验证明？
更进一步，不只是批判论文，还要反向提炼：
这篇论文中有什么方法论、思想或现象，可以成为自己的研究素材？

八、可执行的选题流程
可以把冯越的方法落成下面八步：
1.建立目标领域的完整能力和问题地图。
2.按企业需求、主流关注度和实际价值筛选问题。
3.找到每个问题与成熟领域之间的本质对应关系。
4.收集假说、现象、理论和范式级的高价值 tag。
5.构造“领域问题 × 思想 tag”的组合矩阵。
6.用 AI 和文献检索验证新颖性、合理性与已有进展。
7.把宏大蓝图拆成一个可验证、可发表的局部问题。
8.检查动机、机制、领域适配和实验闭环。
总体而言，冯越反对的是“追着单篇论文打补丁”，推崇的是：
先建立领域全局观，再积累跨领域的高层思想；以真实能力缺口作为动机，以可迁移的理论或现象作为 tag，通过严密对接形成研究问题。
